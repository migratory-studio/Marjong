## 5. 論点A：公開リポジトリの扱い（**決定済み**）

**決定: テストプレイ募集の前に、GitHub Pro へ加入してリポジトリを private 化する。**

### なぜ Pages 側の設定では足りないか

- 問題は Pages ではなく **リポジトリの `Code → Download ZIP`**。素材一式がフォルダ構成のまま落ちる
- **Pages サイト自体の限定公開（アクセス制御）は GitHub Enterprise Cloud 限定**で、個人アカウントでは選べない
  > "To publish a GitHub Pages site privately, your organization must use GitHub Enterprise Cloud."
  > "Access control is available for project sites that are published from a private or internal repository"
- **GitHub Free は public リポジトリでしか Pages を使えない**ため、private 化するには **Pro（$4/月）以上**が必要

### private 化で何が変わるか

| | 変わる | 変わらない |
|---|---|---|
| ZIP 一括DL | ✅ 塞がる（fork 0 件・watcher 0 なので取得経路は完全に消える） | |
| テスターの遊び方 | | URLで今までどおり遊べる（Pagesサイト自体は公開） |
| 開発者ツールでの素材1枚取得 | | 可能なまま。**これは塞ぐ必要がない**（こぱんだ屋が「抵触しない」と明言） |

### 切り替え時の注意

- private 化の直後に **Pages の設定（Settings → Pages）が生きているか確認**する。プランが Free のままだと Pages が止まる
- 独自ドメインを使っていない限り、URL（`migratory-studio.github.io/Marjong`）は変わらない
