## Part 1. リサーチ要約：検証済みの設計原理

開発者一次資料(STS GDC2019 / Hades kasavin)中心。各claimは3票中2票で棄却の対立検証を通過したもののみ採用。

| # | 原理 | 確度 |
|---|------|------|
| **P1** | 唯一最適解(one true build)を作らない。全カードに居場所を与え、相互接続した複数の小シナジー集団(クラスター)を「どれも十分成立する」状態に。全選択を歪める(warping)カードは避ける | 高(STS一次) |
| **P2** | 決定の"前"に開示される運(input randomness)は熟練を活かす／決定の"後"に確定する運(output randomness)は主体性を削るので多用しない | 高 |
| **P3** | 熟練メタ＝「運に賭ける」でなく「分散を管理する」こと。強さを保ちつつ不運に強いビルドを組むのが上級戦略 | 高(Balatro作者一次) |
| **P4/P5** | 面白さは「考えて選ぶプロセス」そのもの。ランごとの差異が再現不能な"一期一会のデッキ"を生み、その不可逆性自体が魅力 | 中 |
| **P6** | 死と再走を"物語の継続"へ転換(主人公は本当には死なない／ボスは前回を覚え勝敗をカウント／関係の蓄積) | 高(Hades一次) |
| **P7** | 死を罰でなく非懲罰的な遷移として設計。物語が死を越えて持続し、ランに費やした時間が無駄に感じられない | 高(Hades一次) |
| **P8** | 難易度が物語進行をゲートしない。story動機のプレイヤーは技量に関わらず先へ進めるべき | 高(Hades一次) |
| **P9/P10** | 計測駆動で均衡(中心指標＝カードpick率・勝利ビルド出現率)。ただしデータは"証拠"であって"結論"ではない | 高(STS一次) |

### 否決された俗説（設計根拠に使わない）
- 「失敗ランも無駄でないよう永続報酬が必須」→**棄却**（物語継続で代替するのが正。ご褒美で釣るのは誤り）
- 「アーキタイプ→彫琢の2段階デッキ構築」→**棄却**（特定機構の根拠なし。"クラスター"が正しい枠組み）
- 「メタ進行(恒久強化)は熟練を損なう」→**棄却**（恒久強化そのものは悪ではない）
- 「最悪RNGでも一定距離は保証すべき」「3層乱数アーキテクチャ」→**棄却**

## Part 2. ギャップマップ：原理 × 現状

| 原理 | 現状の楼光の館 | 評価 |
|------|--------------|------|
| P1 シナジークラスター | カードの大半が `dealMul/takeReduce/maxHp` のフラット加算スタック。カード同士が噛み合わない。異能札6種は孤立。warping気味カードあり(+80%与ダメ) | 🔴 最大の空白 |
| P2 input/output乱数 | ドラフト/進路は input(良)。対局はオート観戦化で output 支配。異能(lucky-draw/zero-search)は本来 output→input 変換装置なのに6種・回数制で過小 | 🟡 武器が眠る |
| P3 分散管理メタ | deal偏重(dealCap 3.0→2.4 に下げる必要が出たほど)。防御/分散管理が攻撃と同格でない。突然死は翻数モデルで改善中(方向◎) | 🟡 攻め一辺倒 |
| P4/P5 一期一会 | 引き継ぎ枠が非累積(◎)。だがラン内の決定は機会コストが薄い | 🟡 決定が軽い |
| P6/P7/P8 物語=メタ進行 | 遭遇イベント5+選択時セリフ+ラン後「絆が少し」のみ。ラン横断の物語なし。「記憶を映す塔」の完璧なHades型フレーム未使用。ボスはプレイアブルキャラなのに"覚えていない" | 🔴 本作の核なのに空白 |
| P9/P10 計測駆動 | `rogueliteLog.js`→Supabase、`test/roguelite-balance.mjs` 掃引、`RL_TUNE`集約。STSと同じ思想が既にある | 🟢 強い |

**結論**：強みは運用基盤。空白は P1(シナジー) と P6(物語)。両方の最良の解決素材が「麻雀×異能」という守るべき軸そのもの。

## Part 4. 提案A 詳細仕様：異能クラスター改革

### 4.1 ねらい（P1 を満たす）
フラット加算スタックを、**互いに掛け算で強化し合う「流派(クラスター)」**へ再編する。
- 各流派は**単独で十分勝てる**（=複数の有効ビルド／one true build 回避）。
- カード同士に**edge(相互強化)**を持たせ、「この札とこの異能が噛むと跳ねる」瞬間を作る。
- warpingカード(単体で全選択を歪める巨大数値)は分解し、流派の文脈で初めて強くなる形へ。
- **異能をビルドの中心軸**に据える＝守る軸「麻雀×異能」が主役化。

### 4.2 流派(クラスター)分類 ＝ ハイブリッド（戦略名 × キャラ哲学）【確定 2026-06-24】
**編成原理＝ハイブリッド**：戦略名の流派に、各キャラの異能を「核」として割り当てる。
P1(機械的クラスター)とキャラ愛着・提案B(記憶の塔)の両取り。4本で開始し、**博打(`gamble`)を5本目として追加済み**(守備の真逆＝高分散ダイヤル)。

| 流派ID | 名称 | 発火条件 | スケーラ(バフ/道具) | 分散 |
|--------|------|---------|-----------------|------|
| `tempo` | 速攻 | ツモ和了 | lucky-draw核＋連勝(波に乗る)・先手の気構え | 中 |
| `flush` | 染め么九 | 染め手(混一/清一) | rootou核＋一色への傾倒・孤高の一色 | 高 |
| `value` | 打点ドラ | 満貫以上 | dora-pull核＋背水リーチ・倍返し・打点への布石 | 高 |
| `guard` | 守備耐久 | (常時)被ダメ上限を**締める** | danger-sense核＋被ダメ軽減・庇い＝**分散管理・低(P3)** | 低 |
| `gamble` | 博打 | どんな和了でも(anyWin) | 乾坤一擲・火事場・丁か半か。被ダメ上限を**上げる**(諸刃) | 最高 |

> ※キャラ固有(signature)異能(charybdis/kakeha-ruina/zero-search/amber-shield/bibi)は札配りしない方針(決定③)のため、博打はバフ駆動のリスク増幅クラスターとして実装。守備(締める)↔博打(上げる)で「分散のダイヤル」が完成＝研究P3を遊びの選択に。

> 注：分類は「2段階構築(否決された俗説)」ではなく、STSの**相互接続クラスター(P1)**として実装する。
> 混色は許容（どれも成立するが、染めるほど edge が効く）。

### 4.2.1 配れる異能＝「札版」は本人より弱い固定版【確定 2026-06-24】
流派の核を供給するため配れる異能プールを拡張するが、**キャラ固有(signature)異能は札配りしない**（amber-shield/charybdis/bibi 等＝そのキャラの魂はそのキャラだけ）。流派の核は**汎用版**で用意する。
- **札版の異能は、そのキャラ本人が使う版より性能を低くする**（本物は本人が握ってこそ＝特別感の保護）。
- **札版はスキルレベルで強化されない**（固定params。`skillRuntimeAbilityParams` の段階強化は本人専用。札由来 grant は弱い固定値を使う）。
- 実装：grant 由来の異能は「弱い固定params」で生成する経路を設け、`skillLevel` 連動を切る。本人装備の異能（修行完了キャラの固有能力）は従来どおり skillLevel で伸びる。

### 4.3 シナジー機構＝しきい値ブレイクポイント主体【確定 2026-06-24】
既存の**動的バフ precedent**（係数を `run.mods` に積み、対局中に `rlApplyDynamicBuffs` で評価）を踏襲。新規エンジン不要。
**緩い線形スケールは採らない**（フラット加算の焼き直しになり現状の問題が再発するため）。**しきい値(breakpoint)で跳ねる**形を主体に、一部に変質(transformation)を混ぜる。

1. **クラスタータグ**：各カード/異能に `cluster: "flush"` を付与（マスタに1行）。`run.mods.clusterCount[cluster]` を `applyCard` 時に集計。
2. **シナジー effect.kind を追加**（`cardEffects.js`）。値は state 依存で対局中に解決：
   - `clusterThreshold`（**主体**）：`cluster` の枚数が `at`(例:3) 以上で `bonus` が発火（例「染め札3枚で"開眼"＝染め手の与ダメ+60%」）。段階(at:3→at:5)で複数ブレイクポイント可。
   - `transform`（**一部**）：`requires:[abilityId]` を持つとき、対象カードの効果が別物に変わる（例「rootou を持つと染め札が国士聴牌の被ダメ無効を付与」）。
   - `comboReward`：対局中の事象(役満/染め直撃/連勝N)で発火する一回性ボーナス。
3. **legible化**：ドラフト/編成で「【染め】3枚で開眼（現在2枚／あと1枚）」のように**ブレイクポイントまでの距離**を表示（P4「考えて選ぶ」＝"あと1枚"の緊張）。
4. **warping分解**：`deal-up-legend(+80%)` 等を「染め手のときだけ大きい」条件化で流派へ吸収しつつ、混色用の**汎用グルー札を2〜3枚だけ残す**（"全カードに居場所")。

### 4.4 データモデル変更（最小・後方互換）
- `rogueliteCardMaster.js`：各カードに任意 `cluster` フィールド追加（未指定=無所属＝従来どおり）。
- `cardEffects.js`：
  - `freshMods()` に `clusterCount:{}`、新動的係数フィールドを追加。
  - `applyEffect` に `clusterScale/synergyIf/comboReward` の積み込み分岐を追加。`applyCard` で `cluster` を集計。
  - 既存 kind は不変（後方互換）。
- `main.js` の `rlApplyDynamicBuffs`（対局中評価）に新係数の解決を追加。
- UI（`rogueliteScreen.js`）：所持パネル/ドラフトに流派バッジ＋シナジー現況。

### 4.5 計測（P9/P10）
`rogueliteLog.js` に追加：
- `buff` イベントに **pick率算出用**：提示された3枚(offered)と選択(picked)を記録。
- `run_end` に **勝利ビルド出現率用**：最終 `cards[]`＋到達深度＋主流派(最多cluster)。
- ダッシュボード観点：流派別の到達深度中央値・各カードのpick率/勝利ビルド出現率で「全カードに居場所があるか」を検証。**データは証拠であって結論ではない**（feel優先で按分）。

### 4.6 校正（必ず終わる設計は維持）
- 被ダメ青天井(`floorDamageMul`/翻数モデル)は不可侵＝どの流派でも必ずランは終わる。
- `test/roguelite-balance.mjs` の harness に**流派別greedy**（染め重視/守備重視/速攻重視のpickポリシー）を追加し、**各流派の到達深度中央値が近接**（=どれも成立／一意最適解なし）になるよう RL_TUNE/BUFF_TUNE を掃引。`--assert` を流派均衡アサートへ拡張。

### 4.7 実装スライス（レビュー可能な縦切り）
1. ✅ **スライス1（足場＋染め么九流・実装済み 2026-06-24）**：クラスタータグ＋**しきい値シナジー**を端から端まで。
   - データ：`rogueliteCardMaster.js` に `cluster` タグ／`CLUSTER_META`／`CLUSTER_SYNERGY`（flush：3枚で開眼+50%・5枚で極み+110%・段は累積しない）／`clusterOf`。染め札＝`grant-rootou`(核)＋`flush-omote`(common)＋`flush-tetsu`(rare)。
   - ロジック：`cardEffects.js` に `clusterCount` 集計（`applyCard`）／`clusterDealMul(run,ctx)` 解決／`clusterProgress(run)` legible素。新規 `effect.kind` は不要（シナジーは流派レベルで定義）。
   - 対局結線：`main.js` `rlApplyDynamicBuffs` が `r.result.yaku` で染め手(混一/清一)を検出し `clusterDealMul` を与ダメへ合流（味方和了時のみ）。
   - UI：ドラフトカードに流派タグ、所持パネルに「染め N枚（3で開眼・あと1）/開眼×N」進捗（`styles.css` に `.rl-card-cluster`/`.rl-cluster-chip`）。
   - 回帰：`test/roguelite.mjs`（802・集計/しきい値/段/legible/後方互換/シリアライズ往復）＋`--assert`(9)＋smoke 緑。
   - 残：実機 feel 確認（染め手和了の跳ねは単体テストで×1.5/×2.1 を確定済み）。校正は流派が出揃うスライス4でharness化。
2. ✅ **スライス2（守備耐久流・実装済み 2026-06-24）**：分散管理メタ(P3)を成立させる守備流。
   - シナジー＝**攻めの逆＝被ダメ上限を締める**：`CLUSTER_SYNERGY.guard.takeCap`（3枚で1局被ダメ上限0.30＝鉄壁／5枚で0.20＝不抜）。事故スパイクを抑える＝分散低減そのもの。
   - データ：`grant-danger-sense`(核)＋既存の守備カードを `cluster:"guard"` へ集約（薄い守り/堅い構え/踏ん張り/庇いの守り/不動の城壁）。`CLUSTER_META.guard`（呼称＝鉄壁・色=緑）。
   - ロジック：`cardEffects.js` に `clusterTakeCapFrac(run)`（達成段の最小cap）。`clusterProgress` を攻め/守り両対応に一般化（`synDescriptor`）。
   - 被ダメ結線：`run.js` `damageContext` が `lethalCapFrac` と守備capの **min** を取る（深度で緩む既定上限を守備札で押し戻す）。
   - UI：流派チップを呼称別に（攻め=開眼／守り=鉄壁）。守備タグ(緑)・混色で染め(青)と同居。
   - 回帰：`test/roguelite.mjs`（821・takeCap解決/被ダメクランプ/混色独立/鉄壁呼称）＋`--assert`(9)＋smoke 緑。実機で守備2/3/5枚＋混色の表示を確認。
3. ✅ **スライス3（速攻/打点流派＋再配置・実装済み 2026-06-24）**：4流派を出揃わせ、deal系を別トリガーで差別化。
   - **発火条件の差別化**：染め＝染め手(flushWin)／速攻＝ツモ和了(tsumoWin)／打点＝満貫以上(bigWin)。同一局で複数該当なら掛け合わせ＝混色コミットのご褒美。
   - シナジー：`CLUSTER_SYNERGY.tempo`(ツモ和了3で+40%/5で+90%)・`value`(満貫以上3で+50%/5で+110%)。`CLUSTER_META` に速攻(加速・金)/打点(会心・橙)。
   - 再配置：幸運のツモ/中張/牌寄せ/波に乗る→tempo、ドラ手繰り/背水/倍返し/必殺の構え/天衣無縫→value。各クラスターに確実到達用の common スケーラ追加(tempo-sen/value-tame)。汎用グルー(一服の茶/鋭い打点/厚みの点棒/猛攻の極み等)は無所属で残す。
   - 結線：`main.js` `rlApplyDynamicBuffs` が `r.tsumo`/`r.result.han|isYakuman|total` で tsumoWin/bigWin を判定し `clusterDealMul` へ。
   - 回帰：`test/roguelite.mjs`(849・3トリガー差別化/タグ/掛け合わせ/単独該当)＋`--assert`＋smoke。
   - **残（スライス4へ）**：warping札(天衣無縫+80%/必殺+45%)の数値de-warp（フラットを下げ条件側へ寄せる）は、harnessを流派対応に再校正するスライス4で実施（数値変更で--assertが動くため）。
4. ✅ **スライス4（計測＋均衡校正・実装済み 2026-06-24）**：データで「全カードに居場所」を担保(P9)し、流派均衡を回帰で固定(P1)。
   - **計測2指標**：`rogueliteLog` の `buff` に offered/picked を必ず記録(カード別pick率)、`run_end` に最終 cardIds＋clusters＋mainCluster(勝利ビルド出現率)。全イベントに `clusters/mainCluster` を同梱(`rlBuffSnap`)。
   - **harnessの流派モデル化**：`simBattle` が味方和了に `clusterDealMul` を本番同経路(battleMods.dealMul)で適用。トリガーは速攻=ツモ(honest)/打点=満貫≥8000(honest)/染め=確率近似(FLUSH_SIM_RATE=0.5・シムは手牌を持たないため)。守備capは `rogueliteDamageDeltas` 内で自動。

### 4.9 博打(gamble)流派＝5本目・高分散ダイヤル（実装済み 2026-06-24）
