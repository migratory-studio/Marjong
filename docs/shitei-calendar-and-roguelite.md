## このゲームの立ち位置（三位一体）

- **能力付き麻雀ゲーム**（点棒＝HP）
- **キャラ愛着傾倒**（師弟で仕込む）
- **ローグライトのある珍しい遊び体感**（修行完了キャラを持ち出して使い倒す）

師弟で愛着を仕込み → 修行完了キャラでそれを持ち出し → 対戦/ローグライトで使う、という線を通す。
**修行完了データが3コンテンツの接続ハブ**（従来「師弟と対戦が独立」課題の構造的解）。

## A. 師弟＝サクセス暦化（体感補強に振り切る）

立ち位置は **愛着形成 ＋ シナリオ閲覧** に振り切る。

### 暦と九宝の開催

- **4月始まりの年度**。時間の流れを「○ヶ月目」だけでなく季節で見せる（ウマ娘感）。
- **九蓮宝燈杯＝4月・年1（最終のみ）**。8宝を揃えた年の4月だけ点灯。頂上決戦は春＝有馬感。
- **八宝（九蓮以外8つ）は半年周期（年2回）で開催**（`tournamentMaster.openBaseMonth` ＋6ヶ月）。月によって複数が同時開催され、**大会メニューから自由に選ぶ**（既得宝も再挑戦可＝ソウル/経験稼ぎ。宝は二重取得しない）。実力不足の大会は既存 `tournamentGate` が門前払い。
- **7/10/1月＝ティア節目の"本大会"**（格付けの山場）。四季の節目感はここで保つ。

### 進行の背骨（不可侵）

- 進行の背骨は **キャンペーン順（`MENTOR_CAMPAIGN`）のまま**＝シナリオの縦軸そのもの。`shiyue-leveldesign-pacing` の「won ゲート不可侵」を維持。
- **暦は「次の宝がいつ開催されるか」を被せるレイヤー**にすぎない。キャンペーン順は触らない。
- 師弟ホーム右下を「**大会へ**」ボタンに（常に有効＝大会メニューを開く）。メニューで当月開催から選ぶ。
- ボタンに目標宝の開催状況を添える（「目標を含む大会、開催中」／「目標は○月（あと○ヶ月）」）。メニュー内では**目標（次の宝）に★マーク**、既得は「制覇済」、実力不足は「門前払い必至」を事前表示。

### クリア尺とペース

- **クリア約2年強（案A'確定）**：春→春を2巡し、九蓮は**3年目の4月＝25ヶ月目**（`dayCount` 25）。現状の校正（9宝≈22〜28ヶ月）にほぼ一致＝**再校正ほぼ不要**。`dayCount` 1＝1年目4月／13＝2年目4月／25＝3年目4月。
- **粒度（コードの真実）**：1ターン＝ゲーム内「ひと月」（`dayCount` の中身は月）／**1ヶ月＝3行動**（`ACTIONS_PER_DAY`）。大会出場も1行動。
- 八宝を半年周期で巡り（育成が追いつき次第どれでも挑める）、最後に九蓮。クリア尺は九蓮アンカー（3年目4月）で担保。

### 難易度の再校正（2年なら軽微）

- クリア約2年（≈22〜28ヶ月）は既存 `test/leveldesign.mjs` の校正前提とほぼ一致＝**再校正ほぼ不要**。
- 暦導入で変わるのは「各宝をいつ開催するか」だけ。**各宝の到達月と oppLv カーブがズレないか**を `test/leveldesign.mjs` で確認する程度でよい。

### シナリオ解禁

- **解禁＝大会優勝でOK**（ちゃんと育てていれば道中オートで十分なアドバンテージが付き、優勝難度は高くない想定）。
- シナリオ最新を閲覧すると「**次のシナリオまで**」の条件表示モーダル。
  - 細ゲージ（実質 0 or 1）。左に弟子、右に師匠アイコン。
  - 条件達成でゲージがアニメで100%→師匠が光る「**シナリオ解禁！**」→次シナリオ誘導モーダル。

### 修行完了データの分離（接続ハブ）

- ゲームデータに **「修行中」自キャラ** と **「修行完了」自キャラ** の2種を持つ。
- 修行完了データは **フリー対戦・ローグライト等の対戦コンテンツで使用可**（現状モックなので **DB作成だけでOK**）。
- **1人5枠**まで保存。**6体目を卒業させたら、どの枠を外すかプレイヤーが手動で選んで入替**（自動押し出しはしない）。
- 卒業（エピローグ読了）で完了スナップショットを作ったら、**修行中データはアーカイブ**して新しい弟子の育成を始められる（余生プレイ＝二人打ち等は別途 `clearedMul` で継続できる設計あり）。

**CompletedAvatar（卒業スナップショット）**：

```js
{
  completedAvatarId, sourceAvatarId, completedAt,
  // 見た目・人物
  name, profileText, mentorCharacterId, presetIds,
  // 戦闘（凍結）
  skillTemplateId, skillLevel,   // ★能力＝修行時のまま固定（卒業後変更不可）
  params6,                       // ★ロール確定の素
  avatarLevel, avatarHpMax, bondLevel,
  // 結果
  role,                         // ★タイプ＝ロール（後述）
  result: { rank, clearMonths, treasures, tournamentPlacements },
}
```

**能力 と タイプ（ロール）の区別**：

- **能力＝`skillTemplateId` + `skillLevel`** を**凍結**（幸運のツモ等。卒業後は変更不可）。
- **タイプ＝ロール**＝既存 `src/data/characterMaster.js` の `ROLE_MASTER`（**attacker / blocker / gambler**）。
- ロールは**育成した `params6` の最終配分で結果確定**（fire・speed→アタッカー／guard・mental→ブロッカー／gamble→ギャンブラー）。**師匠のロールがベース傾斜**（仕様「ほぼ師匠タイプに依存」）＋育て方で寄る＝「育て方の証」。`paramAffinity` で狙って寄せられる（後悔回避）。

**保存先**：ローカル＝`profile.completedAvatars[]`／クラウド＝**`completed_avatars` テーブル**（`companion_bonds` 専用テーブル分離の先例に倣う）。`profileRepositoryFacade` で二系統を束ねる。

### エピローグ後「修行成果」（新仕様）

- エピローグ＋エンドロール閲覧後に「修行成果」を表示。
- 評価軸＝**修行完了までの月数 ／ 雀荘・修行・大会での勝敗（順位）数** →「満貫級〜役満級」（`PLACE_RANKS`）。
- **弟子のタイプ決定**（ほぼ師匠のタイプに依存）。

### 九宝コレクション表示（蓄積の可視化）

データは既存（`records.treasures` ＝獲得済み宝配列、`tournamentById`/`TREASURE_RANKS`）。**新規データ不要・表示するだけ**。

- 大会メニュー上部に **「九宝コレクション」9枠**：獲得＝点灯（宝名＋象徴）／未獲得＝シルエット。
- **現在の段位（○蓮○士）併記**（`treasureRankFor`）。
- 各大会カードに **制覇バッジ**（未制覇／制覇済✓）。
- 挑戦先が所持済みなら「この宝は獲得済み（再挑戦＝記録更新のみ）」。
- 9枠が1つずつ灯り最後に九蓮で繋がる＝タイトル「九蓮宝士」の回収＋最終決戦の重みづけ。

## B. ローグライト（対戦の新しい遊び方）

麻雀 ＋ ローグライト。点棒＝HP が HP管理・撤退判断・ダメージ計算と地続き。

### 卓モデル（✅確定）
- **既存ペア戦エンジン（同卓2対2）を流用**＝「味方陣営 vs 敵陣営の同卓」がすでにある。**新規エンジン不要**。
- **パーティ最大3人**（**修行完了弟子を含められる**）。卓には味方2人が着席して敵2を削る。**3人目は控え**（パッシブ能力源／戦ごとに交代）。

### ラン構造（✅エンドレス）
- **エンドレス**：階層を登り続け、**最深到達階層を記録**（クリア概念なし＝記録更新型）。
- 数階ごとに**ボス層**（ネームドライバル `tournamentRivalMaster`／モブ `mobMaster` を流用）。
- 1戦＝**浅い階1局・深い階2〜3局**（「1局戦/2局戦/3局戦」）。約3分。
- 各戦後に **継続 or 撤退**。撤退＝**到達記録＋報酬＋引継ぎバフを確保して帰還**／全滅＝**ラン没収**（非対称リスク）。

### HP／ダメージ（点棒＝HP・独自スケール）
- ローグライト専用HPスケール（**序盤敵1000**〜階層で増加）。味方は `avatarHpMax` をこのスケールに正規化。
- 和了＝敵HPを削る／放銃・被ツモ＝味方HP減。**飛ばし（HP0）で撃破**。
- 「与ダメ倍率／被ダメ軽減」＝和了点の割増／失点の軽減。

### バフ・カタログ（素案）
HP回復／HP最大値＋／与ダメ倍率＋／被ダメ軽減＋／**＋1名仲間（控え追加）**／能力強化（`skillLevel` 一時＋）／`params6` 一時ブースト／配牌グレードUP・ドラ確定・リーチ自動 等。

### レア度（素案）
コモン→レア→エピック→レジェンダリ。レア率UP要因＝**相手を飛ばした**（詩玥の点棒嫌いと緊張＝物語の燃料）／**点差で大きく上回った**／**到達階層が深い**。

### メタ進行＝ローグライク（✅確定）
- **進度（到達階層）に応じて、次回ランに引き継げるバフ枠数が決まる**（深く行くほど枠が増える＝正のフィードバック）。
- **ラン終了時に、獲得バフから引継ぎ枠ぶんを選択**。次ラン開始時にそのバフを持ってスタート。
- **累積しない（✅確定）**：毎ラン終了時に枠数ぶん選び直し＝手持ちは常に「次の1ランぶん」。インフレせず、エンドレスの難度逓増と釣り合う（恒常強化は修行完了キャラ側が担う＝役割分担）。

※オンライン協力プレイは将来構想（仕様ざっくりのため一旦割愛）。

### 二層構造（固有性 × 一回性）

- **キャラ固有能力**（修行時固定＝その子の個性）× **ラン内バフ**（毎回違うビルド）。
- テーマ的緊張：**「飛ばすほど高レア」と詩玥の"点棒嫌い"が衝突**＝物語の燃料に使える。
